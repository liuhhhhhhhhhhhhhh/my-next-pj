# Next.js Testing

- 官方文档：<https://nextjs.org/docs/app/guides/testing>

## 测试分层

| 类型 | 适合验证 |
|---|---|
| Unit | 函数、工具、Hook 的局部行为 |
| Component | 组件渲染和用户交互 |
| Integration | 多个模块组合后的行为 |
| E2E | 浏览器中的完整用户流程 |

## 实用建议

- `async` Server Components 对部分单元测试工具支持有限，关键页面优先用 E2E 测试。
- 登录、表单提交、重定向、权限不足和错误页面应作为完整流程测试。
- 测试缓存和重新验证时，验证“用户写入后看到什么”，不要只测试函数是否被调用。
- 测试 API 时同时覆盖成功响应、校验失败、未授权和异常响应。

## 和知识图谱的关系

Testing 横跨页面、数据、认证、错误处理和部署，是把知识从“知道”变成“可验证”的方法。
